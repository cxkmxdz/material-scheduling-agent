# 素材审核与发布排期 Agent 技术说明

真实模型只决定下一项动作，业务工具负责取数、审核和持久化。运行器负责校验、预算、Trace 和从证据重建结果。这个边界让模型遇到不同观察时可以改变动作，同时避免把模型自述当成保存或审批事实。

## 决策循环

`RealModel.decide` 在每轮构建 system 约束、用户请求、函数定义及全部历史工具调用与结果，向可配置 Chat Completions 端点请求一次原生函数调用。响应解析成 ToolAction 或 FinalAction，参数由 Pydantic 再校验。运行器执行工具，追加结构化观察，再次调用模型。没有固定的真实模式动作序列，也没有运行器自动重试。

模型可以补查窗口、提出替代、观察保存错误后重试或结束。最多 24 轮模型决策和 24 次工具调用；默认值从计划建议的 12/16 调整为 24/24，以支持已交付的多素材样例。大批量素材可能需要显式提高预算；无论输入多少项均受上限保护。一轮仅接受一条函数调用，最终使用 finish，便于审计和兼容。

模型响应错误、超时、鉴权失败、429 额度或频率限制、网络错误返回明确错误码并终止；不做隐藏重试。非法业务工具或错误参数返回工具观察，模型有机会修正。finish 不接收草稿 ID 或完成状态，最终结果根据 SQLite 和可信证据计算，提前结束会返回 incomplete。

实测 DeepSeek 官方端点的 thinking 默认值不支持 required 工具选择，因此该主机默认显式 disabled；其他服务仅在用户设置 MODEL_THINKING=disabled 时发送该扩展字段。Trace 保留 HTTP 状态、响应 ID、返回模型名和 token 数以追溯实际请求，不保留错误体或内部思维链。三组对照报告同时验证工具观察顺序、后续模型动作和数据库，避免把 API 失败当作业务故障验收通过。

`MockModel` 为确定性观察驱动脚本，只验证相同循环和业务工具，不能证明真实模型决策。HTTP 适配器测试亦使用假响应。

## 工具和证据

| 工具 | 责任 | 保存所需证据 |
| --- | --- | --- |
| read_material | 读取素材、列出关键缺失字段、读取已存在草稿 | 当前运行的素材元数据 |
| check_rules | 对已读元数据执行演示规则，返回规则 ID 和风险级别 | 当前运行的 passed 审核结果 |
| query_slots | 按渠道读取已确认排期和占位草稿，返回逐小时时段 | 提议时段已查询且当时可用 |
| save_draft | 验证证据、推导确认状态、事务内复查并保存 | 不接受模型传入的审核或确认值 |

所有工具返回 ok、code、data、summary。工具只处理 request.material_ids 内的素材；额外参数被拒绝。模型模块不持有 Repository，也没有 SQL、文件写入或发布函数。审核证据是当前运行内工具产生的状态，不接受模型自行提供的通过字段。

## 时间和确认边界

每项素材固定占用 1 小时。区间采用 `[start,end)`；重叠公式为 `existing.start < candidate.end AND existing.end > candidate.start`。因此 18:00–19:00 与 19:00–20:00 不冲突，18:30–19:30 会同时影响两个候选小时。同渠道才互相影响。数据库时间统一 UTC，时区等价写法生成同一请求摘要。

hard 要求改变时间，save_draft 自动标记 pending_confirmation；原始请求完整保留。flexible 允许窗口内调整，无需额外确认。待确认草稿不占用时段，所以不同建议可能指向同一小时；这是有意保留的建议语义。符合要求的普通草稿占位，避免后续重复预约，但不等同已发布或用户确认。未来增加确认动作时必须重新审核和检查冲突，本项目不提供该动作。

## SQLite 幂等和保存失败

requests 表以 request_id 为主键，保存规范化 JSON 与 SHA256。规范化排序素材 ID，并转换时间到 UTC；其他内容变化视为不同请求。同 ID 同内容可恢复原草稿；同 ID 不同内容报 REQUEST_ID_CONFLICT。草稿表同时有 draft_id 主键及 `(request_id, material_id)` 唯一约束。

注册和保存均用 BEGIN IMMEDIATE。保存事务依次验证请求摘要、查询已有子项、复查冲突、INSERT、commit。并发相同子项只返回一份记录；不同请求竞争同一占位小时只能有一个成功。SQLite 设置外键和 5 秒连接锁等待；数据库异常显式返回，不忙等。

故障注入在 INSERT 后执行不存在表的 SQL，使 SQLite 实际抛出错误，事务上下文执行 rollback。失败不返回生成中的 UUID。每个素材最多两次新保存尝试；错误观察返回给模型，是否重试由模型决定。最终再查询数据库，草稿 ID 和 saved 状态来源于持久记录；最终核验失败时不声称保存成功。

## Trace 和依赖

JSONL 每条包含 run_id、mode、model、step、action、tool_arguments、observation_summary、tool_status、decision_summary、timestamp。工具观察完整写入，最终结果亦写入。仅保存简短公开决策说明，不采集模型内部思维链。密钥在序列化前递归脱敏，API 错误体不写日志；文件独占创建以保护旧证据。

Python 标准库完成 SQLite、CLI 和 JSON；Pydantic 2.12.3 校验，httpx 0.28.1 接 API，python-dotenv 1.2.1 加载配置，pytest 8.4.2 验证。uv.lock 锁定全部版本。没有使用 Agent 框架，减少隐藏重试和框架状态，也便于评审定位每次工具执行。
